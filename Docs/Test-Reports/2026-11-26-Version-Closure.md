## 真实问题与修复

1. 微距相关照片请求曾只指定一个 constituent，真机在 capturePhoto 时抛 NSInvalidArgumentException，要求至少两个。现请求超广角及另一个组成镜头，仍只保留超广角交付结果；RAW 和包围请求维持原路径。当前官方 SDK 的 `AVCapturePhotoOutput.h` 在该属性说明中明确要求至少两个组成镜头；网页摘要只写子集。本轮真机异常也确认了这一约束。
2. 星轨异步迁移后，短时长截止可能发生在第一帧处理期间，旧零帧判断会丢弃这一帧。现在等待已提交帧处理完成后输出，真正尚无帧时仍取消。
3. 退出相机不能取消已开始的最终合成。星空照片和星轨保留 finishing 状态，星空延时等待已提交渲染排空后再完成视频，释放采集路由与完成输出独立处理。
4. 延时非标准输入比例中心裁切后未把图像原点平移回零，可能在输出缓冲留下空白。已补齐平移；以线性 0.18／0.36 输入验证平均输出约 0.27，并检查旧拍摄 ID 无效。

- 电影影调用例仍期待旧明显抬黑及彩色高光逐通道不变。按当前影调约束检查低抬黑、灰阶单调、HDR 高光亮度保留及色度收敛；未为测试改动影调算法。
