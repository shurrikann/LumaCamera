# 2026-10-26 前后同步双拍：基础版定向验证

## 当前能力

前置视频页的广角按钮保持居中，右侧新增轻量双拍按钮；默认后置主摄为大画面、前置为圆角小窗，点按小窗交换，交换使用既有取景过渡，不移动其他控件。画中画直接合成为一个带声音的视频，沿用单次 AVAssetWriter 编码和现有 SDR 滤镜、编辑路径。

首版仅开放实际测试的 HEVC、SDR、1080p30、16:9，输出竖向 1080×1920；不开放其他分辨率/帧率、HDR/Log、ProRes、Open Gate。开启时切到基础规格，关闭恢复此前普通视频规格；进入其他视频子模块或切回照片时先退出双拍。A/M 参数操作面向当前主画面，按其硬件范围约束显示值；录制白平衡锁定同时作用于两路。物理拍摄按键的扩展参数菜单在此独立会话中暂不开放，界面参数操作保留。

双拍保留现有相机页横拿时只旋转控件的布局；尚未增加独立的横向双拍输出轨道/可拖动小窗。较小的前置图像被裁切后用于合成，交换为大画面不代表获得原生全传感器照片清晰度。其他设备和 iOS18–26 兼容分支未做实机验收，不能用本机结果替代。

## 官方依据及实现边界

- Apple [AVMultiCamPiP 示例](https://developer.apple.com/documentation/avfoundation/avmulticampip-capturing-from-multiple-cameras)：前后输入显式连接到各自视频输出，在编码前合成画中画。参考其主路回调驱动、缓存最近副路帧的方案；本实现只缓存一张，并要求 PTS 差不超过 2/30 秒，超时不重复烧录陈旧副画面。这不是硬件同步快门保证。
- [AVCaptureMultiCamSession](https://developer.apple.com/documentation/avfoundation/avcapturemulticamsession)：逐个检查格式的 `isMultiCamSupported`、连接、硬件/压力成本，并真实启动、录制、解码；不把单摄规格或设备原生相机的私有能力当作公共 API 保证。
- `AVCaptureDevice.RotationCoordinator` 的 iOS27 SDK 官方声明 `videoRotationAngleRelative(toDeviceOrientation:)` 明确各镜头原生方向可不同。本机读取后置竖屏90°、前置0°，分别配置连接，不统一硬编码90°。iOS18–26暂沿用官方旧方向接口，存在弃用提示，尚未实机验证。

`DualCaptureSource` 独占 MultiCam 图，普通会话先停止；合成和写入同在 recordingQueue，预览队列最多一个待处理任务；四缓冲阈值限制像素池分配。停止、取消、运行错误后先停机拆连接，再恢复原格式/倍率。后台保留意图、停止实际采集，回来只启动当前选中的一个会话。系统中断和严重相机压力提供退出/终止保护，真实电话中断及高温路径尚未人工复现。

## 修复过程与保留的失败

1. Source4使用严格PTS同步器，185回调没有一张可合成帧；两传感器PTS不同。已切换官方示例的有界最近副帧方式，不能把最终方案描述成硬件同时曝光。
2. Engine初轮后台返回会拆除双拍路由；生命周期保留意图后通过。
3. Orientation初轮方法执行通过，但检查文件发现前置侧转；已改用逐镜头官方角度。Orientation2保留前后交换文件附件，方法通过不等于所有设备姿态已验证。
4. FinalRegression/FrontRecovery发现返回前置照片缺少动态画幅。追踪证明“先从视频进入前置”保存的是1920×1080、dynamic=0的格式。现在此分支从官方动态画幅/照片尺寸能力中保留照片格式；FrontRecovery2和ControlsFinal相关项通过。
5. Finish的冷启动失败：保存的前置标准倍率1.6000在新格式变为1.5855，完整焦段ID不相同。双拍存档现在有前置标准路线后备，Cold及ReleaseChecks实际启动通过。
6. Finish的前置主体大小对照失败（宽约13.3%、高约10.0%），当轮未固定姿态，不能据此断言原因。用户固定竖持、人物静止后，PortraitCompare的同一断言通过：竖幅宽/高差约1.63%/1.22%，横幅约0.85%/1.13%。原失败日志保留，不计为已通过。

原始日志/xcresult位于 `/private/tmp/LumaCamera-DualCapture-20261026-*`。主要通过轮次为ControlsFinal（7项）、Orientation2（1项）、PortraitCompare（1项）、ReleaseChecks（3项，含重叠方法）。指标与方法列表见 [结构化结果](2026-10-26-DualCapture-results.json)。

尚未验证长期录制、高温/耗电量、独立生产App内存、其他机型、横向输出及全部系统中断；不把测试进程内存、框架成本或快照耗时当作相机实际功耗/FPS。

最终正常App构建 `FinalApp.log` 为 `BUILD SUCCEEDED`；已通过有线CoreDevice安装并启动 `com.shurrikann.LumaCamera`（安装序号12056）。启动命令成功不另外计作一项硬件验收。

## 后续：入口看不见的定向修复

用户反馈前置视频也找不到入口。旧实现把无背景的白色图标放在前置广角分支内，并偏移到基础按钮边界外；现改为完整焦段区域内的独立40点圆形玻璃按钮，广角仍居中。EntryInspect真机截图已能看到未选中的新按钮，但几何断言失败；DEBUG过渡视图退出清理可能覆盖新记录，因此此按钮改为仅在入口实际隐藏时清理，不改变正式按钮动作。

EntryFinal两项通过：未开启状态A/M两帧均为(229,574,40,40)，均落在焦段父区域(68,572,266,44)内，不遮挡旁边控件；窗口命中视图可见。该命中检查和模型触发不等同于人工触摸按钮。10次快速请求、开关/退出、原三轮录制/小窗交换回归通过，未开启状态可见性用例总计约4.60秒（包含相机切换/等待，不是渲染FPS）。累计12个不同方法有通过记录。原EntryVisibility/EntryInspect几何失败日志和截图保留。

当前小窗仍不可拖动；只支持固定位置与点按交换主副画面，未将本次技术讨论记为已实现拖动。
