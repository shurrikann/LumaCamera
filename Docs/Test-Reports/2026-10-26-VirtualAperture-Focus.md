# 2026-10-26 虚拟光圈与对焦专项检查

## 代码与官方依据

虚拟光圈是输入帧完成采集后的CI星芒处理，没有设置focusMode/lensPosition/focusPointOfInterest。参数连续调节仅提交look，不重新配置对焦导航；开关可能关闭互斥子模块，并在前置/超广角时选择主摄，这类路由改变会影响近距对焦能力，不能归因于软件光圈改变光学景深。自动微距仍由系统虚拟多摄决定，实际超广角帧暂停星芒。

官方[focusPointOfInterest](https://developer.apple.com/documentation/avfoundation/avcapturedevice/focuspointofinterest)说明设置兴趣点后需要设置autoFocus/continuousAutoFocus才启动调焦；项目普通点按遵循该路径。软件效果没有进入系统自动对焦分析输入。

## 真机验证

iPhone17 Pro / iOS27.0.1，专项方法最终20.851秒通过，无拍摄、无系统相册写入。新增DEBUG硬件快照焦点坐标/调焦状态字段及相关测试，没有修改生产对焦行为。

- M挡主摄1×、长焦4×/8×，各0.25/0.75两个镜头位置，共6组。每组开启效果、60次连续光圈提交、松手、关闭效果，实际lensPosition约0.25098/0.75294，模式保持locked，坐标和设备不被效果改写。
- 三个倍率×开关两状态×两个点，共12次点按。输入(0.3,0.5)/(0.7,0.5)变换后实际传感器坐标(0.5,0.7)/(0.5,0.3)，continuousAutoFocus正确；随后光圈4→16不改变模式或焦点坐标。配置完成墙钟约5–36ms，不是最终合焦耗时或屏幕FPS。
- 主摄/4×从0.10196初始锁焦位置释放后，0.8秒窗口内观察到镜头移动并结束调焦。8×部分样本保持0.10196，开启时另一样本0.18824仍在调焦；开关两状态都有未移动样本，不能确认8×所有目标最终清晰，也不能据此认定星芒造成AF失败。
- A挡三轮开关、最大光圈及复位，硬件连续AF模式和兴趣点保持。

首轮测试误将逻辑镜头数量固定为2，设备实际主摄1×+长焦4×/8×共3项，数量断言失败；其余执行记录未发现硬件焦点被改写。修正枚举预期后最终通过。第二轮启动被锁屏阻断，解锁后继续成功。

结果包`/private/tmp/LumaCamera-VirtualAperture-Focus2.xcresult`，日志同名前缀`.log`。未量化照片光学清晰度、实际近远主体最终合焦误差、弱光/长时性能或其他设备，不把硬件模式正确等同所有场景保证。当前局部高亮提取也会在面光源边缘产生星芒，是视觉算法限制，尚未实现按亮区面积/形状排除面光源。

检查后普通Debug构建通过，正常应用安装序号12544。
测试后正常版启动被手机锁屏阻断（CoreDevice Locked），不记录为启动通过；应用已安装，可解锁后手动打开。
