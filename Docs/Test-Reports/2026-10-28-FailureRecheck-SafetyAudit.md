# 78项失败复验：相册写入隔离审计

自动审批拒绝了原逐项脚本，原因是异常收尾可能恢复默认视频保存回调。此次不是直接重跑原脚本：诊断构建新增 DEBUG + 显式环境变量 LUMA_DIAGNOSTIC_READ_ONLY_PHOTOS=1 的默认服务隔离。

AppDependencies.makeCameraModel：显式替身沿用；未指定替身时，在该诊断环境统一使用 DiagnosticReadOnlyPhotoService。该服务没有 PHPhotoLibrary.performChanges/asset change request，save/saveCapture/saveVideo/saveLivePhoto/delete单项与批量六个入口只失败回调并打印拦截记录。浏览方法只转发到 PhotoBrowserService 协议（协议不含修改接口）。因此即使迟到回调恢复到默认 CameraViewModel.onVideoRecorded，也无法写入 Photos。

只读开关会写入独立 .xctestrun 的测试宿主 EnvironmentVariables，绝不写入正常scheme或用户偏好；普通App无此变量，Release无该分支。Apple本机man xcodebuild.xctestrun明确该字段传入测试宿主进程。

安全门控先执行 CaptureReviewEntryTests/testDiagnosticPhotoIsolationBlocksAllMutationEntrypoints 和 testDiagnosticEnvironmentProtectsDefaultModelCallbacks：验证六个入口、恢复的默认录像回调，以及未显式注入服务的默认照片/视频回调均被拒绝。

78个选择都来自原671项已审计清单，无SystemPhotoLibraryService直接保存/删除用例；外接RAW实盘方法仍排除。ProResRAW的本次方法只取RAW元数据，不写文件。SlowShutterSequencePhysicalTests创建专用SlowShutterMemoryLibrary，仅内存收片；其余捕获本地回调，出现异常落入默认服务也被此隔离拒绝。72项自动，6项需要现场配合。

本轮测试逻辑/断言和相机功能未修改；只有诊断相册依赖注入及自检变化。和原全量比较必须披露这层测试隔离差异。
