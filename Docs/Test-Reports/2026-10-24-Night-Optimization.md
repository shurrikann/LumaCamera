# 2026-10-24 夜景融合优化

## 范围与依据

用户反馈夜景与普通照片接近。本轮保持原有三帧 −1/0/+1 EV 请求、格式条件和环境门限，优化合成质量，不直接增加硬件请求张数。不修改界面、普通拍照参数、自动微距选择、其他子模块或视频。

公开 API 依据：[曝光包围](https://developer.apple.com/documentation/avfoundation/capturing-a-bracketed-photo-sequence)、[Vision 平移配准](https://developer.apple.com/documentation/vision/vntranslationalimageregistrationrequest)、[曝光调整](https://developer.apple.com/documentation/coreimage/ciexposureadjust)、[Core Image 降噪](https://developer.apple.com/documentation/coreimage/cinoisereduction)。苹果提供这些采集/图像处理工具，未提供本项目使用的夜景触发阈值、融合权重或运动判断参数；算法均为应用实现，不是原生 Night mode 的复刻。

## 实现

- 以中间曝光为参考，所有有效帧参与交集，避免旧代码跳过第一张有效帧的交集检查。
- 曝光增益从排除近黑/近白像素的线性化亮度比中位数估计，范围 ±2 EV；先归一再融合，避免直接混合 −1/0/+1 EV 导致整体变暗。
- 根据归一后的 RGB 差异降低移动区域权重，参考曝光始终保留。不使用全局模糊/旧帧叠加改变预览。
- 暗部混入适度 CINoiseReduction，使用保留黑白端点的曲线提升暗部；无新增全局锐化。
- 至少两张对齐且中间曝光存在时保存真实 2/3 帧融合；单张时保留参考原片，缺少参考时沿用可用帧回退。不把单帧标记为多帧。
- 诊断及相册月亮标识同时兼容 2/3 帧记录；中间曝光 EXIF 保持代表单张曝光，不能将其曝光时间称为累计积分。
- 新增/修改核心逻辑有中文注释。DEBUG 临时原片回调允许获取夜景中间曝光，只供同次拍摄对照。

## 环境与结果

设备 iPhone 17 Pro，iOS 27.0.1（24A446），原项目签名；真实相机、临时内存回调和 XCTest 附件，不保存系统相册，无模拟器或镜像。

1. `/private/tmp/LumaCamera-Night-Optimize-Unit.xcresult`：6 项通过。确定性噪声、运动区域、部分对齐、单帧回退、旧配准重复及标识持久化。首轮没有曝光归一，后续实拍发现偏暗，未作为最终效果交付。
2. `/private/tmp/LumaCamera-Night-Optimize-Physical.xcresult`：1 项通过、3 次三帧实拍；耗时 1.929/1.387/1.379 秒。目视发现旧曝光融合仍拉低亮度，因此继续修正曝光归一。
3. `/private/tmp/LumaCamera-Night-Optimize-Normalized.xcresult`：**10 项通过，9.140 秒**。3 次实拍均报告“3 帧对齐融合”；JPG 两次、HEIF 一次。提交至回调 **1.561/1.765/1.702 秒**，中位 **1.702 秒**，包括采集、解码、配准、融合和编码，不含相册保存，不是快门时间/FPS。相机会话错误审计无错误；保存队列未增加。
4. 同次拍摄中间曝光与最终成片附件已目视对照：本场景暗部更明亮、噪声更低，未见明显重复物体；样片主体本来有失焦和遮挡，不能作为细小纹理、人物运动或全部场景画质验收。临时附件在 `/private/tmp/LumaCamera-Night-Optimize-Normalized-Attachments`，不写入仓库/应用资源。
5. 实际文件的快门和焦距逐次与原生中间曝光 EXIF 比较，通过；源/输出快门均 1/60 秒，输出含 ISO 800。没有用详情页文字代替文件核对。该轮没有系统照片 App 保存检查，未验证全部 GPS/TIFF 字段。
6. `/private/tmp/LumaCamera-Night-Optimize-Final.xcresult`：**9 项通过，7.951 秒**。4 轮快速夜景开关、1 次相机退出/重新激活、1 次退出夜景后普通拍照无夜景诊断/标识；无会话错误、无相册写入；单帧/无效输入安全回退。已对七种照片比例的横/竖输出共 14 种进行 JPEG 编码尺寸断言，未改 UI 布局。

性能与像素基准：真机 320×240 合成夹具，固定独立噪声种子。12 次真实 CI 渲染（包含探针、CPU 遮罩和输出渲染），最终中位 **138.6 ms**，P95（本样本取最大）**147.6 ms**。10400 个平坦暗部像素的 8-bit 通道标准差 **7.240 → 2.073**；此数仅是合成测试图，不代表实景噪声下降百分比、传感器信噪比或细节保留程度。曝光归一后亮度、运动物体不留红色残影、原有未过曝亮部不剪白均有像素断言。

## 边界与后续

- 帧数仍固定三帧；两帧/单帧是异常容错，并非环境自适应。未新增更长曝光积分、光流、旋转/透视配准、学习式去噪或完整运动分割。
- 实拍用例强制三帧请求，以独立覆盖硬件管线。本场景读数 ISO 800、1/60 秒，未达到原有自动夜景门限；环境门限的确定性规则/滞回/重置检查通过，不能宣称本场景自然触发验收。正常使用仍需橙色月亮才实际启用夜景。
- 运动保护/增益估计是启发式，复杂局部色调映射、低纹理、快速运动及旋转可能降低有效融合；只有单帧时不强行合成。
- 只验证短时重复，未测长期温升/能耗/纯应用内存，没有声称全量功能验证。夜景单次静态采集没有新增取消 API；本轮覆盖关闭/退出和重入、无效帧回退，未注入采集中进程终止。
- 日志出现系统 `mdb_txn_commit / MDB_MAP_FULL` 缓存信息；本轮捕获及像素检查均完成，未将其当作已修复或保证无系统日志问题。
