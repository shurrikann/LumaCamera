# 2026-11-10 旧版 vs 新版 Energy A/B

设备：iPhone 17 Pro，iOS 27.2.1；Debug 构建；`Power Profiler`，`ProcessSubsystemPowerImpact` 1s 采样。测试期间 USB 连接 Mac，处于充电状态；旧版和新版供电条件一致。
旧版基线：`f25db90` + 仅测试用 DEBUG 启动参数补丁。
新版：`d834f1d`（含水平仪按需、Log2 LUT 预合成、低电量/热压力预览上限、视频待机录制输出关闭）。
测试入口：DEBUG `--perf-video` 自动进入视频待机；`--perf-record=300` 自动录制 5 分钟后停止。

## 原始均值（impact 单位）

| 场景 | CPU | Display | GPU | 热状态 | 加权亮度 |
|---|---:|---:|---:|---|---:|
| 旧版待机 10m | 2.219 | 2.251 | 0.046 | Nominal | 95.5% |
| 新版待机 10m | 2.255 | 1.692 | 0.046 | 6.88m Nominal → 3.15m Fair | 77.5% |
| 旧版录像 5m | 2.527 | 1.513 | 0.045 | Fair | 73.4% |
| 新版录像 5m | 2.387 | 1.586 | 0.062 | Fair | 80.8% |

## 观察

- 录像段 CPU 均值：新版 −5.5%（2.527 → 2.387）。
- 录像段 GPU 均值：新版 +35%（0.045 → 0.062），但 GPU impact 量化很粗，不能单独下定论。
- 待机段 CPU：新版 +1.6%，基本持平；新版后半段进入 Fair，处于更不利状态。
- Display Impact 受亮度和热状态强烈影响：旧版待机亮度 95.5%，新版 77.5%，不能直接说新版显示功耗下降 25%。

## 结论

本轮没有证明整体功耗下降。录像 CPU 有改善信号，但 GPU 反向变化；待机段受热状态/自动亮度污染，Display 对比无效。

## 下次复测要求

1. 关闭自动亮度，固定屏幕亮度（建议 80% 或 100%）。
2. 每次开始前设备回到 Nominal，段间冷却。
3. 旧/新版交替顺序（ABBA），至少 2 次。
4. 仍用 10m 待机 + 5m 录像；分析 CPU/GPU 与亮度归一化后的 Display。
5. 同时导出 `device-thermal-state-intervals` 和 `DisplayBrightnessLevel`。

## 2026-11-10 受控重测

- 条件：同一 USB 充电器，测试入口每次锁定 UIScreen 亮度 80%，每段前冷却 8 分钟；10m 视频待机 + 5m 录像。
- 旧版 `f25db90` + 相同测试入口；新版当前 `809043a` 之后构建。
- Power Profiler 同时取 `ProcessSubsystemPowerImpact` 和实际 `ProcessCPUUsage`；CPU 使用率按 10ms 采样均值。

## 结论

- 录像段实际 CPU +0.5%、GPU +2%、Display +0.3%，属于持平；Power Profiler 的 CPU impact 在新版录像显示 +16%，与实际 CPU 使用率不一致，不能作为回归结论。
- 待机段实际 CPU −0.9%，但新版更早进入 Fair，Display impact 更低主要来自热降亮/显示策略，不能算优化收益。
- 之前的 46 vs 110 Log LUT、48 vs 256 照片滤镜没有参与待机/录像路径，本轮 A/B 测到的主要是：水平仪按需、视频待机录制连接、预览帧率策略；其中待机连接和水平仪没有可测收益。
- 建议：待机录制连接开关收益不足，考虑回退以降低复杂度；Log2 预合成和低电量预览上限本轮未覆盖，需单独测试。
